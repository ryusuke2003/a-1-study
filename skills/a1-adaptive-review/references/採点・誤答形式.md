# 採点後のSessionと誤答記録

採点時だけ読む。出題前の構造は [問題・採点形式](問題・採点形式.md) に置く。

## 採点追記

回答後に、専用スクリプトが各問題へ次を追記する。

```markdown
### 採点

Score: <100|0> / 100
Result: <correct|incorrect|unknown>
Next Review: YYYY-MM-DD
```

通常の問題Sessionの採点欄には、正誤・不明を問わず `#### 解説` を付けない。解説は不正解・不明の「間違えた問題」記録にだけ保存する。

採点欄は必ず、その問題の選択肢と次の `### Qn` 見出しの間に置く。最終問では選択肢の直後に置く。追記後、各問題に `### 採点` が一つだけあり、問題番号と採点結果がずれていないことを確認する。

## Session完了監査

採点は回答済みの設問だけを抜き出して処理しない。対象Sessionの全設問を一つのマニフェストで処理し、専用スクリプトがヘッダを次のように更新する。

```markdown
- Status: graded
- Graded: YYYY-MM-DD
- Grading Audit: questions=<n>, graded=<n>, correct=<n>, incorrect=<n>, unknown=<n>
```

`Question Count`、実際のQ見出し数、採点欄数はいずれも `questions` と一致させる。Q番号は `Q1` から連番とする。各問の選択済みは0または1個とし、0個は未選択の `unknown`、複数選択は不正として扱う。不一致、欠番、重複、採点欄の位置ずれがあれば、先にSession構造を直してから採点する。

問題数に上限はない。20問は出題時の既定値にすぎず、30問・49問以上でも、対象Sessionの全問を同じ監査単位として採点する。作業を分割しても、全問数と `graded` が一致するまでSessionを完了にしない。

採点結果はカードの `Last Reviewed`、`Next Review`、`Stage`、`Last Result` にも反映する。同じカードを再復習した場合、カード一覧の現在値と照合するのはそのカードの最新採点だけとし、過去の採点欄は当時の履歴として保持する。Eと未選択の `Result` は `unknown`、それ以外の誤答は `incorrect` とする。複数選択は不正な入力として適用を停止する。

## 間違えた問題の記録

不正解または `unknown` の問題だけを、専用スクリプトが採点日ごとの `学習記録/間違えた問題/YYYY-MM-DD.md` に追記する。別日のファイルにコメント化した複製を残さない。

```markdown
# YYYY-MM-DD 間違えた問題

## Session <元のSession番号> / Q<元の問題番号>: <Card ID>

- Source Session: <元の問題ファイルを一意に特定するリンク>
- Your Answer: <学習者が選んだ選択肢>
- Correct Answer: <正解の選択肢>

### 問題

<問題文>

### 模範解答

<正解の選択肢を、選択肢記号と本文で記載する>

### 解説

- A: <元の選択肢Aの本文><br>
  → <選択肢Aの用語の定義・本来の役割・この設問で正誤となる具体的理由>
- B: <元の選択肢Bの本文><br>
  → <選択肢Bの用語の定義・本来の役割・この設問で正誤となる具体的理由>
- C: <元の選択肢Cの本文><br>
  → <選択肢Cの用語の定義・本来の役割・この設問で正誤となる具体的理由>
- D: <元の選択肢Dの本文><br>
  → <選択肢Dの用語の定義・本来の役割・この設問で正誤となる具体的理由>

<正解となる仕組み・条件と各選択肢との差を、上の選択肢別説明で具体的に示す。カード要点の転載や一般論だけで終えない。>
```

各 `- A:`〜`- D:` 行には元の問題Sessionの選択肢本文をそのまま載せ、末尾に `<br>` を置いて表示上の改行を保証し、その直下の `→` 行に解説を置く。解説を選択肢本文の再掲だけにしたり、`この用語が表す役割・概念です`、`設問の条件には合わない`、`正解とは区別する`、`正解の選択肢です` のような定型文だけにしたりしてはならない。

この「問題」「模範解答」「解説」は、不正解・不明の記録には必須であり、この順で記載する。一方、正答を含む通常の問題Sessionの採点欄には原則として解説を付けない。
