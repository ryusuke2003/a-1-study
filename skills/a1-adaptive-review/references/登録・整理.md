# 学びの登録・整理

1. 自由文を、用語・定義・比較・条件・因果・手順に分ける。
2. 主分野を決める。必要なら関連分野も記録する。分野は既存配置だけで決めず、試験シラバス上の位置付けも確認する。
3. 既存ノートと同じ内容なら統合し、異なる観点は追記する。
4. 核となる知識を一枚の復習カードにする。
5. 次のどれかに該当する直接周辺知識を、必要な分だけ追加でカード化する。
   - 同じ問題の誤答選択肢、対になる概念、混同しやすい概念
   - 成立条件・前提・例外
   - 仕組みの役割、主体、入力・出力、手順の前後関係
   - 正解を判断するために必要な頻出の基礎事項
6. 周辺カードと核カードの関連は、`Source` ノート内に `Related To: A1-xxxx` と理由を記録する。カード一覧は既存の8列を維持し、存在しない補足列やカード本文ファイルを作らない。出題時はSessionの `Related To` に転記する。
7. 過去問由来の学びでは、詳しい説明の正本である `学んだこと/` を先に更新し、その対象解説ブロックを開催回別の `過去問/<開催回>解説.md` に同一内容で同期する。
   - `過去問/` はリポジトリ直下に置き、同一開催回は一つのファイルへ追記する。既存ファイルを確認し、「秋期／秋季」など表記違いだけで同じ開催回のファイルを分裂させない。
   - 開催回又は問題番号を確実に特定できない場合は推測してファイルを作らず、確認するか `要確認` とする。
   - 同期対象は `<!-- past-exam-sync: 過去問/<開催回>解説.md#<問題識別子>:start -->` と同じキーの `:end` で囲む。例：`#午前I-問1`。正本側と過去問側で、マーカー間の本文を完全一致させる。
   - 既存キーがあれば新規ブロックを重複追加せず、そのブロックを更新する。内容変更は `学んだこと/` を先に行い、過去問側だけを独立して編集しない。
   - 過去問解説側にはカードの状態を複製しない。カードの要点・状態の正本は引き続き `復習カード/カード一覧.md` とする。
8. 不確かな記述や質問は `要確認` として保存し、事実として問題化しない。

一つの問題やテーマから、核1個と周辺2〜6個程度を目安に回収する。ただし数を満たすためだけの追加はしない。登録しても問題Sessionは作らない。

カードの要点・状態は `復習カード/カード一覧.md` の該当行だけを更新する。未採点の `Last Reviewed` は `-` とする。採点に伴う状態更新は専用スクリプトに任せる。ノートや履歴を全件読み込まず、対象分野・カードIDで必要箇所を参照する。
