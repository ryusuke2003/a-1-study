# A-1 適応復習

他教材で学んだ内容の整理と想起練習を支援する。試験範囲を先回りして網羅的に教えない。

## 共通ルール

- 問題は学習者が明示的に依頼したときだけ作る。登録・整理・採点・状況確認から自動出題しない。
- 登録内容・既存カードと、理解や区別に直接必要な周辺知識に限定する。`要確認` の内容は事実として出題しない。
- Markdownを正本とする。カードの要点・現在状態は `復習カード/カード一覧.md` の8列、詳しい説明は `Source` の `学んだこと/` ノート、出題・採点履歴は `学習記録/復習問題/` に置く。カード本文の複製を作らない。
- JST午前5時に学習日を切り替える。00:00〜04:59は前日の学習日とする。
- 採点によるカード・履歴更新は専用スクリプトだけで行う。作業用JSON・正解配置表は `/tmp` に置き、公開・コミットしない。pushは明示依頼時だけ行う。

## 作業別に読む文書

該当する行だけ読む。複合依頼では必要な行を組み合わせる。スクリプトは実行し、通常操作でソース全文を読まない。改修・障害調査時だけ実装を読む。

| 作業 | 必須の参照 | 処理 |
|---|---|---|
| 登録・整理 | [登録・整理](references/登録・整理.md) | 対象ノートとカードを更新。出題しない |
| 問題作成 | [出題手順](references/出題手順.md)、[問題・採点形式](references/問題・採点形式.md) | 既定20問。件数上限ではない |
| 採点 | [採点マニフェスト](references/採点マニフェスト.md)、[採点・誤答形式](references/採点・誤答形式.md) | prepare → 全問判断 → dry-run → apply |
| 状況確認 | 追加の参照文書なし | カード一覧から期限超過・当日期限・直近誤答／不明を報告 |

## 問題を作るとき

通常の復習問題を作る前に、`scripts/select_review_cards.py --count <問題数>` を実行し、その結果を出題候補とする。問題数の指定がなければ20問とする。20問は出題時の既定値であり、Sessionの上限でも採点対象の上限でもない。

選出数にかかわらず、候補は次の比率を基準に配分する。端数は合計が指定数と一致するよう調整する。

- 約70%: 期限超過・当日期限
- 約20%: 直近が不正解または `unknown`
- 約10%: `unreviewed` または近日期限

同じカードは一つのSessionで一度だけ選ぶ。期限枠では期限超過日数、直近評価の低さ、長く出題されていないことを優先する。不正解・不明枠と未復習・近日期限枠も `Next Review` が早いものを優先する。ある枠の候補が足りない場合は、未選出カードを期限と直近評価の順で補充する。利用可能なカードが指定数より少ない場合は重複出題せず、選出可能な件数を学習者へ伝える。

スクリプトは選出集合を変えず、同じ分野が連続しにくい順に並べる。問題作成時には、さらに直近の問い方との重複を確認する。特定テーマを指定された場合は通常配分を使わず、そのテーマの核カードと周辺カードをまとめて選んでよい。どちらの場合も、問題記録には元となったカードとの関連を残す。

選出日を明示して再現したい場合は `--on YYYY-MM-DD`、機械可読な結果が必要な場合は `--format json` を付ける。`--on` を省略した場合、JST午前5時で学習日を切り替える。

### 短期集中で網羅を目指す場合

学習者が短期集中の計画を指定した場合は、問題を作る依頼があった日に限り、次を目安にする。

- 1か月目は、1日20問のうち新規の過去問を10〜12問までとし、残りを復習カードの期限に沿った問題にする。
- 2か月目は新規を穴埋め中心にし、毎日20問の復習を継続する。本番形式の30問・50分演習は週2回を目安とする。
- 新規問題の正答・誤答選択肢を無差別にカード化せず、理解に直接必要な周辺知識だけを追加する。深掘りの量が日々の復習を圧迫する場合は、未整理の周辺知識を後回しにする。

### 周辺知識として追加・出題できるもの

- 対になる概念、または混同しやすい概念
- 仕組みの成立条件・前提・例外
- 手順の前後関係、入力・出力、責任主体
- 登録内容を判断するために必要な頻出の基本事項

出題・回答・採点の Markdown 形式は [問題・採点形式](references/問題・採点形式.md) に従う。

`復習カード/カード一覧.md` が、カードID、分野、要点、Source、最終復習日（`Last Reviewed`）、復習期限、段階、直近評価を持つ唯一の正本である。詳しい説明は `Source` の `学んだこと/` ノートを参照し、カード本文ファイルは作成しない。未採点カードの `Last Reviewed` は `-` とする。登録でカードを変えるときは一覧の該当行を更新する。採点時のカード更新は、下記の専用スクリプトだけに行わせる。

## 採点と復習期限

- 採点依頼を受けたら、[採点マニフェスト](references/採点マニフェスト.md) に従い、`grade_review_session.py prepare` で対象Session全問のJSON下書きを `/tmp` に生成する。複数Sessionが回答済みなら、学習者が限定しない限り各Sessionを対象にする。
- AIが判断・記述するのは、全問の `correct_answer` と `result`、および不正解・不明のA〜D解説だけとする。選択状態の読取り、採点欄挿入、復習間隔計算、カード更新、監査集計、誤答記録の整形は手編集せず、専用スクリプトに一括処理させる。
- JSONは問題番号を省略せず、対象Sessionの全問を一度に完成させる。20問、30問、49問以上でも同じ一回の `apply` に渡し、途中の一部だけを完了扱いにしない。
- `apply --dry-run` で全件を検証してから `apply` を一度だけ実行する。スクリプトはSession、カード一覧、採点日の誤答記録をまとめて更新し、既存の全Session監査に失敗した場合は3ファイルすべてを元に戻す。
- 採点マニフェストは作業用データなのでリポジトリへ保存・コミットしない。
- 専用スクリプトを使えない異常時はMarkdownを部分的に手編集して完了扱いにしない。原因を直してから同じフローを再実行する。
- A〜D の知識選択肢から正解を一つだけ選んだ場合は、推測ではなく想起できた正答として扱い、復習段階を一つ進める。
- 不正解の知識選択肢、`E. わかりません`、未選択は、段階を0に戻し、原則として翌日を次回復習日にする。複数選択は採点入力の不正として適用を停止する。
- 基本間隔は、段階0から順に「当日または翌日、3日、7日、14日、30日、60日、以後はおおむね倍」とする。
- 正答でも一回だけで長期定着とは見なさず、上の間隔で再確認する。
- 正答には解説を付けない。通常の問題Sessionの採点欄には、正誤や不明を問わず解説を一切付けない。誤答・不明の解説は「間違えた問題」記録にだけ付け、各設問ごとに正解となる仕組み・条件を具体的に記述する。さらに、その設問のA〜Dの**全選択肢**を、1行目の `- A: <元の選択肢本文><br>` と2行目の `  → <解説>`（B〜Dも同様）で記録する。`<br>` により表示上も矢印の直前で必ず改行する。矢印行では用語の定義、本来の役割・使う場面、この設問で正解または不正解になる具体的理由を説明する。選択肢本文の再掲だけや、`この用語が表す役割・概念です`、`設問の条件には合わない`、`正解とは区別する`、`正解の選択肢です` のように中身を説明しない定型文は禁止する。

## 状況を報告するとき

カード一覧から、期限超過、今日の対象、直近の誤答・不明を簡潔に示す。まだカードがない場合は、問題を作らず学んだことの登録を案内する。
