# A-1 適応復習

学習者が他の教材で学んだ知識を分野別に整理し、忘れないための復習を行う。試験範囲を先回りして網羅的に教える Skill ではない。

## 作業の境界

- 学びの登録・整理・採点・状況確認だけでは問題を作らない。問題は学習者が「問題を作って」「復習したい」などと明示したときだけ作る。
- 出題の起点は、学習者が登録した内容と既存の復習カードである。
- 学んだ内容の核だけで終わらせず、理解・区別に直接必要な周辺知識まで登録する。関連の薄い範囲を、重要という理由だけで追加・出題しない。
- ノート・カード・出題・採点履歴は人が編集できる Markdown として保存する。
- JST の学習日は午前5時に切り替える。00:00〜04:59 は前日の学習日として扱う。

## 学びを登録・整理するとき

1. 自由文を、用語・定義・比較・条件・因果・手順に分ける。
2. 主分野を決める。必要なら関連分野も記録する。
3. 既存ノートと同じ内容なら統合し、異なる観点は追記する。
4. 核となる知識を一枚の復習カードにする。
5. 次のどれかに該当する直接周辺知識を、必要な分だけ追加でカード化する。
   - 同じ問題の誤答選択肢、対になる概念、混同しやすい概念
   - 成立条件・前提・例外
   - 仕組みの役割、主体、入力・出力、手順の前後関係
   - 正解を判断するために必要な頻出の基礎事項
6. 周辺カードには、元の核カードとの関連を `Related To` と補足欄に記録する。
7. 不確かな記述や質問は `要確認` として保存し、事実として問題化しない。

一つの問題やテーマから、核1個と周辺2〜6個程度を目安に回収する。ただし数を満たすためだけの追加はしない。登録しても問題Sessionは作らない。

## 問題を作るとき

まず、期限超過、当日期限、誤答後、不明／未回答、近日期限の順でカードを選ぶ。同順位では、期限超過日数・直近評価の低さ・長く出題されていないことを優先する。候補がある場合、分野と直近の問い方が偏らないようにする。

問題数の指定がなければ20問とする。これは出題時の既定値であり、Sessionの上限でも採点対象の上限でもない。通常の復習では期限・評価を優先し、特定テーマの復習では、核カードとその周辺カードをまとめて出題してよい。どちらの場合も、問題記録には元となったカードとの関連を残す。

### 短期集中で網羅を目指す場合

学習者が短期集中の計画を指定した場合は、問題を作る依頼があった日に限り、次を目安にする。

- 1か月目は、1日20問のうち新規の過去問を10〜12問までとし、残りを復習カードの期限に沿った問題にする。
- 2か月目は新規を穴埋め中心にし、毎日20問の復習を継続する。本番形式の30問・50分演習は週2回を目安とする。
- 新規問題の正答・誤答選択肢を無差別にカード化せず、理解に直接必要な周辺知識だけを追加する。深掘りの量が日々の復習を圧迫する場合は、未整理の周辺知識を後回しにする。

### 周辺知識として追加・出題できるもの

- 対になる概念、または混同しやすい概念
- 仕組みの成立条件・前提・例外
- 手順の前後関係、入力・出力、責任主体
- 登録内容を判断するために必要な頻出の基本事項

出題・回答・採点の Markdown 形式は [問題・採点形式](references/問題・採点形式.md) に従う。

`復習カード/カード一覧.md` が、カードID、分野、要点、Source、最終復習日（`Last Reviewed`）、復習期限、段階、直近評価を持つ唯一の正本である。詳しい説明は `Source` の `学んだこと/` ノートを参照し、カード本文ファイルは作成しない。未採点カードの `Last Reviewed` は `-` とする。登録・採点でカードの最終復習日、期限または評価を変えたときは、一覧の該当1行だけを更新する。候補選定、問題文・正解・解説の作成、意味的な採点は、このSkillに従ってチャットで行う。

## 採点と復習期限

- 採点依頼を受けたら、回答済みの設問を一部だけ採点して終えてはならない。対象Sessionを先頭から末尾まで走査し、**選択済み・未選択を問わず全設問**を一度に採点する。複数Sessionが回答済みなら、学習者が対象を限定しない限り全て対象にする。
- 問題数が20問、30問、50問などの大きなSessionでも同じ手順を適用する。処理を複数回に分ける必要があっても、途中結果を完了扱いにせず、全設問の採点・カード更新・誤答記録・監査がそろった時点でのみ完了とする。
- 採点開始前に、Sessionごとに「宣言された `Question Count`」「実際の `### Qn` 数」「0または1選択の設問数」「既存の採点欄数」を数える。設問番号の欠番・重複、宣言数との不一致、複数選択、既存採点欄の位置ずれは、採点結果へ混ぜず先に修正・明示する。
- 採点の完了条件は、各対象Sessionで次のすべてを満たすこととする。満たせない限り `Status: graded` にしない。
  1. `Question Count` と実際の設問数が一致し、Q番号が `Q1` から連番である。
  2. 各設問の選択済みの選択肢が0または1個である。0個は未選択として `Result: unknown`、1個は選択内容に基づく結果にする。複数選択は不正として修正する。
  3. 各設問範囲に `### 採点` がちょうど一つあり、全問数と採点欄数が一致する。
  4. カードごとの最新採点について、カード行が最終復習日・採点結果・段階・次回復習日に更新され、不正解／不明の設問が間違った問題の記録に一件ずつある。過去の採点欄は当時の履歴なので、後日の再復習で変化したカード一覧の現在値とは直接比較しない。
- 完了時はSessionヘッダを `Status: graded` に更新し、`- Graded: YYYY-MM-DD`、`- Grading Audit: questions=<n>, graded=<n>, correct=<n>, incorrect=<n>, unknown=<n>` を追記する。これにより回答数と採点数を人が即座に照合できるようにする。
- 採点結果は、**各設問の選択肢の直後、かつ次の `### Qn` 見出しより前**に、その設問の `### 採点` として追記する。一括の「採点結果」節を新設したり、別の設問の途中へまとめて挿入したりしない。
- 採点の追記先は、共通する選択肢行などの曖昧な文字列検索で決めない。対象の `### Qn` 見出しから次の `### Q(n+1)` 見出し（最終問はSession末尾）までを一つの範囲として特定してから編集する。
- 保存前に、全設問について「選択肢 → `### 採点` → 次の設問」の順序になっていること、各設問に採点欄がちょうど一つあることを確認し、上の完了条件を採点対象のSessionごとに照合する。
- `Status: graded` にする直前に、リポジトリ直下で `python3 skills/a1-adaptive-review/scripts/verify_review_sessions.py` を実行する。検査では全 `graded` Session（旧データも `graded` へ移行する）を対象に、問題数、Q連番、選択数、採点欄、ScoreとResult、監査内訳、カードごとの最新採点に対する `Last Reviewed`・`Next Review`・`Stage`・`Last Result`、誤答記録を照合する。失敗した場合は完了にせず、原因を修正して再実行する。
- 不正解、`unknown`、未選択、複数選択の問題は、採点日に `学習記録/間違った問題/YYYY-MM-DD.md` へも追記する。このファイルは採点日ごとの復習用記録であり、各問題にカードID、問題文、**模範解答**、学習者の解答、正解、混同を正す解説、元の問題Sessionへのリンクを必ず残す。見出しは `Session番号 + Q番号 + Card ID`、リンクは元の問題ファイルを特定できるものとし、この4要素を誤答記録の照合キーにする。本文は「問題 → 模範解答 → 解説」の順にする。通常の採点欄には解説を付けない。
- 同じ採点日の誤答は、既存の `学習記録/間違った問題/YYYY-MM-DD.md` に追記する。正答はこのディレクトリへ記録しない。
- A〜D の知識選択肢から正解を一つだけ選んだ場合は、推測ではなく想起できた正答として扱い、復習段階を一つ進める。
- 不正解の知識選択肢、`E. わかりません`、未選択、複数選択は、段階を0に戻し、原則として翌日を次回復習日にする。
- 基本間隔は、段階0から順に「当日または翌日、3日、7日、14日、30日、60日、以後はおおむね倍」とする。
- 正答でも一回だけで長期定着とは見なさず、上の間隔で再確認する。
- 正答には解説を付けない。通常の問題Sessionの採点欄には、正誤や不明を問わず解説を一切付けない。誤答・不明の解説は「間違った問題」記録にだけ付け、各設問ごとに正解となる仕組み・条件を具体的に記述する。さらに、その設問のA〜Dの**全選択肢**を、1行目の `- A: <元の選択肢本文>` と2行目の `  → <解説>`（B〜Dも同様）で記録する。矢印行では用語の定義、本来の役割・使う場面、この設問で正解または不正解になる具体的理由を説明する。選択肢本文の再掲だけや、`この用語が表す役割・概念です`、`設問の条件には合わない`、`正解とは区別する`、`正解の選択肢です` のように中身を説明しない定型文は禁止する。

## 状況を報告するとき

カード一覧から、期限超過、今日の対象、直近の誤答・不明を簡潔に示す。まだカードがない場合は、問題を作らず学んだことの登録を案内する。
