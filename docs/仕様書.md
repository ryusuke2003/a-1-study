# セキスペ A-1 適応復習ノート — 仕様書

## 1. 目的

情報処理安全確保支援士試験の A-1 問題（旧・午前 I）で必要になる知識を、学習者自身が別の教材で学んだタイミングで登録し、忘却曲線を意識して想起練習する。

対象は「これから試験範囲を教える学習システム」ではなく、**既に学んだことを整理・定着させる補助**である。ただし作問時には、登録した知識を理解・区別するために直接関連する A-1 の重要知識を補助問題として扱える。登録内容と無関係に試験範囲を埋める自動作問や、カリキュラムの網羅は必須機能にしない。

## 2. 利用者と基本フロー

利用者は学習者一人を想定する。日常的な操作はチャットで行い、データはリポジトリ内の Markdown に保存する。

```text
学習者が自由文で「学んだこと」を入力
             ↓
分野別の恒久ノートへ要約・整理
             ↓
知識の最小単位ごとに復習カードを作成
             ↓
復習期限に応じた短い問題を生成
             ↓
回答を採点し、カードの次回復習日を更新
```

### 2.1 学んだことの登録

学習者は箇条書き、文章、教材の要約、疑問を含む途中メモなど、形式を問わず入力できる。

登録時には次を行う。

1. 内容を事実・用語・比較・因果関係・計算／判断手順に分解する
2. A-1 の分野に分類する
3. 同じ内容が既存ノートにあれば重複を避けて統合する
4. 復習に値する最小知識単位ごとにカードを作る
5. 不確かな記述や質問は「要確認」として残し、事実として問題化しない

登録段階では、元の説明にない関連知識を恒久ノートや復習対象へ勝手に混ぜない。作問時に関連知識を補う基準は、次節の「関連補強問題」に従う。

### 2.2 関連補強問題

問題を作成する際は、登録済みのカードだけでなく、その学びから直接導ける「出題されやすい」「知っておくと混同を防げる」周辺知識を最大で全体の 40% まで含めてよい。これを関連補強問題と呼ぶ。

関連補強問題にできるのは、次のいずれかに該当するものだけとする。

- 登録した用語と対になる概念、または混同しやすい概念
- 登録した仕組みの成立条件・前提・例外
- 登録した手順の前後関係、入力・出力、責任主体
- A-1 で頻出の基本事項で、登録内容を正しく判断するための直接的な土台

関連性が弱い別分野の知識を、単に重要だからという理由で混ぜてはいけない。問題には元となったカードを紐付け、解説では「どの学びとの関連で出題したか」を記録する。採点後、学習者が今後も復習したいと判断できるよう、補強知識はカードとして保存する。

### 2.3 復習問題の出題

学習者が「今日の復習問題を作って」「復習したい」などと**明示的に依頼したときだけ**問題を作る。登録、整理、採点、進捗確認を行っただけでは問題を作らない。定期的な勝手作問・通知・催促も初期仕様に含めない。

出題対象は登録済みカードと、そのカードに直接関連する補強知識だけである。期限超過・当日期限・苦手なカードを優先する。既に未回答の問題があるカードは、原則として新しい問題に重複して出さない。

### 2.4 回答と採点

学習者は各問題の A〜D と `E. わかりません` のチェックボックスから一つを選ぶ。自信がない場合は推測せず `E. わかりません` を選ぶ。

採点時は、選択結果を次の三段階で記録する。学習者は自信がない場合に「わかりません」を選ぶため、4つの知識選択肢から正解を一つ選べた場合は、推測による偶然の正答とは扱わず、想起できた正答として記録する。

| 評価 | 意味 | 次回復習の扱い |
|---|---|---|
| 正答 | 4つの知識選択肢のうち、正解を一つだけ選べた | 間隔を一段階延長する |
| 誤答 | 不正解の知識選択肢を選んだ | 最短間隔へ戻す |
| 不明／未回答 | 「わかりません」を選んだ、未選択、または複数選択 | 最短間隔へ戻す |

採点後、必要なら恒久ノートへ補足を追加し、誤答理由と次回に思い出すべき一文を記録する。

## 3. 分野分類

登録時は次の一次分類を用いる。複数分野にまたがる内容は主分野を一つ決め、必要なら関連分野を併記する。

| 区分 | 分野例 |
|---|---|
| テクノロジ系 | 基礎理論、アルゴリズムとプログラミング、コンピュータ構成要素、システム構成要素、ソフトウェア、データベース、ネットワーク、セキュリティ、開発技術 |
| マネジメント系 | プロジェクトマネジメント、サービスマネジメント、システム監査 |
| ストラテジ系 | システム戦略、システム企画、経営戦略、技術戦略、ビジネスインダストリ、企業と法務 |

分野ファイルは必要になった時点で作成する。分類に迷う内容は、学習者の元の文脈を優先し、後から移動できる Markdown 構成にする。

## 4. 忘却曲線を意識した復習設計

### 4.1 学習日

日付は JST で扱い、午前 5 時を学習日の切替とする。00:00〜04:59 の登録・採点は前日の学習日に紐付ける。

### 4.2 基本間隔

新規カードは登録後、次の目安で復習候補にする。

| 段階 | 前回からの目安 | 意図 |
|---:|---:|---|
| 0 | 当日または翌日 | 初回の想起確認 |
| 1 | 3日 | 短期記憶からの取り出し |
| 2 | 7日 | 忘れ始めへの介入 |
| 3 | 14日 | 定着確認 |
| 4 | 30日 | 長期記憶への移行確認 |
| 5以降 | 60日、以後はおおむね倍 | 維持確認 |

これは固定の宿題ではなく、次に復習問題を依頼されたときの優先順位である。未学習日があっても期限を消化扱いにはしない。

### 4.3 評価による補正

- 正答: カードの段階を一つ進める。直近でも同じ表現を繰り返さず、問い方を変えて想起を確認する。
- 誤答: 段階を 0 に戻し、原則翌日を次回復習日にする。選んだ誤答が示す混同点を解説し、必要ならノートも補足する。
- 不明／未回答: 段階を 0 に戻し、原則翌日を次回復習日にする。`わかりません` は、知識を推測せず不明として記録するための有効な回答である。

期限超過日数が長いカードほど優先度を上げる。ただし、一回のセッションで同じ分野・同じ知識ばかりにならないよう、候補があれば分野を分散させる。

## 5. 問題の形式

初期仕様の基本は、参照リポジトリの「10分復習」と同じチェックボックス形式の**4択＋「わかりません」選択肢**とする。学習者は A〜D の知識選択肢、または E. わかりません、のうち一つだけをチェックする。回答欄に文章を書くことは必須にしない。

| カードの内容 | 主な問い方 |
|---|---|
| 用語・定義 | X の説明として最も適切なものを選ぶ |
| 役割・因果 | X が必要な理由・防ぐ対象として最も適切なものを選ぶ |
| 条件・制約 | X が成立する条件として最も適切なものを選ぶ |
| 手順・計算 | この状況で行うこと・値の意味として最も適切なものを選ぶ |
| 比較・判断 | この状況で適切な選択または X と Y の違いを選ぶ |

各問題は A〜D の知識選択肢を4つ置き、正解はそのうち一つだけとする。加えて、必ず `E. わかりません` の選択肢を置く。誤答選択肢は、無関係で明らかに誤った内容にせず、役割が近い仕組み、必要だが条件に不十分な対策、条件・主体・適用範囲・順序を一部だけ取り違えた説明にする。正解だけが設問の条件をすべて満たし、複数正解と読める曖昧さを作らない。

一つだけ選択された回答を正答、誤答、または不明として採点する。`E. わかりません`、未選択、複数選択は不明／未回答とする。正答を選んだ場合は推測ではなく想起できた証拠として扱う。ただし、一回の正答だけで長期定着とは判断せず、基本間隔に沿って繰り返し確認する。

一回の通常セッションは既定 5 問、最大 10 問とする。問題数が指定された場合はそれを優先する。期限到来カードが少ない場合は、近日期限または直近に誤答だったカード、直接関連する補強知識で補うが、登録内容と無関係な新規知識は出さない。

## 6. データ構成

すべて人が読める Markdown を正本とする。将来スクリプトを導入しても、スクリプト専用の不透明なデータだけに依存しない。

```text
学んだこと/
  README.md                         # 分野一覧と記入方針
  テクノロジ系/
  マネジメント系/
  ストラテジ系/
復習カード/
  カード一覧.md                     # カードの状態・期限の正本
  {分野}.md                         # カード本文・模範要点
学習記録/
  復習問題/
    YYYY-MM-DD.md                   # 出題・回答・採点結果
  学習履歴.md                        # 実施記録
進捗/
  分野別状況.md                     # 登録数、期限超過、苦手カード
```

### 6.1 分野別ノート

分野別ノートには、学習者が理解した内容を日付見出しごとに要約する。ノートは説明を読み返すための恒久メモであり、カード管理表の状態を混在させない。

### 6.2 復習カードの必須項目

各カードは少なくとも次を持つ。

| 項目 | 内容 |
|---|---|
| Card ID | 変更しない識別子 |
| 主分野／関連分野 | 分野別の集計と分散出題に使う |
| 学んだことへの参照 | 元メモを確認できるリンク |
| 確認したい要点 | 採点で必須とする最小要素 |
| 問題例 | 同じ知識を問う候補表現 |
| 作成根拠 | 学習者の元メモ由来か、どのカードに関連する補強知識か |
| 登録日・最終復習日・次回復習日 | 復習順序の根拠 |
| 段階 | 基本間隔のどこにいるか |
| 直近評価 | 正答・誤答・不明／未回答 |
| 補足 | 誤解しやすい点、学習者の質問など |

## 7. 出題選定ルール

復習セッションでは、候補カードを次の優先順で選ぶ。

1. 未回答の保留カード
2. 次回復習日を過ぎたカード
3. 当日が次回復習日のカード
4. 誤答後で早期確認が必要なカード
5. 選ばれたカードに直接関連する補強知識
6. 近い将来に期限が来るカード

同順位なら、期限超過日数が長いもの、直近評価が低いもの、長期間出題されていないものを優先する。直近セッションと同じカード、同じ問い文、同じ分野への偏りは避ける。

カードがまだ一枚もない場合は、問題を作らず「先に学んだことを登録してください」と案内する。

## 8. チャットで受け付ける依頼例

| 依頼 | 想定する処理 |
|---|---|
| 「これを今日学んだ。整理して」 | 分野ノートへの要約とカード作成（問題は作らない） |
| 「このメモを A-1 向けにまとめて」 | 用語・条件・比較を抽出し、分類して保存 |
| 「今日の復習問題を作って」 | 期限と苦手度に従い、関連補強問題も含めて「4択＋わかりません」の問題を作成 |
| 「3問だけ復習したい」 | 優先度上位から 3 問出題 |
| 「ネットワークだけ復習したい」 | 指定分野のカードだけで出題 |
| 「採点して」 | 回答済みの最新セッションを採点し、期限を更新 |
| 「今の復習状況を見せて」 | 期限超過、今日の対象、分野別の状態を要約 |

## 9. 初期仕様に含めないもの

- 登録内容と関係なく試験シラバス全体から出題すること
- こちらからの自動通知、定時作問、学習催促
- 過去問の自動収集・転載
- 正誤だけを蓄積して、学習者の元メモを残さない運用
- 一問の選択問題正答だけで「理解済み」と判断すること

## 10. 受け入れ基準

初期実装は、少なくとも次を満たせば本仕様に適合する。

1. 自由文で登録した学びを、A-1 の分野別 Markdown ノートに整理できる。
2. 一つの登録内容から複数の最小知識単位をカード化できる。
3. カードごとに次回復習日と評価を記録できる。
4. 復習問題は登録済みカードと、そこから直接関連する重要知識だけから、期限と評価を根拠に選べる。
5. 問題作成は明示的な依頼時にだけ行い、4つの知識選択肢または「わかりません」の一つをチェックして回答できる。
6. 回答の採点後、正答・誤答・不明／未回答に応じて復習間隔を更新できる。
7. 学習者が後から Markdown を読めば、なぜその問題が出たか、次にいつ優先されるかを追跡できる。
