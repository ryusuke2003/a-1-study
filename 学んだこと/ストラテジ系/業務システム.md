# 業務システム

## 2026-08-29

### 生産システムの層とMES

- 生産事業所のシステムは、大きく**計画層・実行層・制御層**に分けられる。
- **計画層**は、生産計画・資材計画・スケジューリングなど、何をいつどれだけ生産するかを計画する。
- **実行層**は、製造指示、工程管理、作業実績・品質・在庫の収集と管理など、計画を現場で実行・進捗管理する。
- **制御層**は、機械・機器を直接制御する。PLCなどがここに位置する。
- **MES（Manufacturing Execution System：製造実行システム）**は実行層で運用され、計画と製造現場の間をつなぐ。問28の正解は **イ**。

| 層 | 主な役割 | 例 |
| --- | --- | --- |
| 計画層 | 生産量・時期・資材などを計画する | 生産計画、スケジューリング |
| 実行層 | 製造の指示・進捗・実績を管理する | MES |
| 制御層 | 機械・機器を直接制御する | PLC、センサー制御 |

## 2026-09-01

### PLC（Programmable Logic Controller）

- **PLC（Programmable Logic Controller：プログラマブルロジックコントローラ）**は、工場の製造設備や機械を自動制御するための産業用コントローラである。押しボタン、リミットスイッチ、各種センサーなどから入力を受け、あらかじめ作成された制御プログラムで条件を判断し、モーター、ランプ、ヒーター、電磁弁などへ出力する。
- PLCの基本動作は、**入力を読み取る → 制御プログラムを実行する → 出力を更新する**という処理を繰り返すことである。この一連の周期を**スキャンサイクル**と呼ぶ。通信処理や自己診断なども周期内または周期の合間に行われる。
- 通常の入出力更新は周期的に行われるため、入力の変化から出力へ反映されるまでの時間にはスキャン時間が関係する。通常のスキャンでは捉えにくい高速な変化には、高速入出力や割込み処理などを用いる。
- `Programmable` は、リレーを配線し直して制御回路を変更する方式と異なり、プログラムを書き換えて制御ロジックを変更できることを表す。代表的なプログラミング言語には、リレー回路に似た**ラダーダイアグラム（LD）**、テキスト形式の**ストラクチャードテキスト（ST）**、**ファンクションブロックダイアグラム（FBD）**などがある。

| 処理 | PLCが扱う内容 | 例 |
| --- | --- | --- |
| 入力 | 現場の状態を信号として読み取る | センサー、押しボタン、リミットスイッチ |
| 演算 | 入力と内部状態を制御プログラムで判断する | インターロック、タイマー、カウンター |
| 出力 | 判断結果に従って機械・機器を動かす | モーター、電磁弁、ランプ、アラーム |

### PLC・MES・計画システムの違い

- 覚え方は、**MESは工場・工程全体を「管理・指示」し、PLCは現場の機械を「実際に制御」する**である。MESは製造指示や進捗・実績を管理する実行層、PLCはセンサー入力を受けてモーター・電磁弁などを動かす制御層に位置する。

| 層 | 役割 | PLCとの違い |
| --- | --- | --- |
| 計画層 | 何を、いつ、どれだけ生産するかを決める | 生産計画を立てる層であり、機械を直接制御しない |
| 実行層（MES） | 製造指示、進捗、実績、品質、在庫を管理する | 製造現場全体の実行を管理するが、個々の機械の入出力制御はPLCが担う |
| 制御層（PLC） | センサー入力を基に機械・機器へ出力する | 現場の機械を直接、自動制御する |

- MESとPLCは置き換え関係ではない。MESがPLCなどの制御層へ製造条件や指示を渡し、PLC側から設備状態や生産実績を受け取ることで、実行層と制御層が連携する。

## 2026-09-06

### エッジAIにおける学習と推論

- **エッジAI**は、センサー、カメラ、スマートフォン、産業機器など、データが発生する場所に近いエッジデバイスでAI処理を行う仕組みである。クラウドへの往復を減らせるため、低遅延、通信量削減、オフライン動作、データを外部へ出さないことによるプライバシー保護などに向く。
- **学習（training）**は、データから識別・予測などを行うモデルを作る処理である。**推論（inference）**は、学習済みモデルへ新しい実データを入力し、識別・予測などの結果を得る処理である。
- クラウドで学習し、学習済みモデルをエッジデバイスへ配布して、その場で推論する構成がある。「学習したモデルに従い、実際にデータの識別などを行う」は推論なので、問27の正解は **イ**。

| 選択肢の説明 | 該当する処理 |
| --- | --- |
| 環境内で試行錯誤し、行動への報酬を基に学習する | 強化学習という**学習** |
| 学習済みモデルに実データを入力して識別する | **推論** |
| 正解ラベル付きデータからモデルを作る | 教師あり学習という**学習** |
| 正解ラベルなしデータからモデルを作る | 教師なし学習という**学習** |

### 過学習とデータ拡張

- **汎化性能（generalization performance）**は、学習に使っていない未知のデータに対しても、学習で得た規則性を適用して正しく識別・予測できる能力である。訓練データの正解を丸暗記する力ではなく、新しいデータにも通用する力を指す。
- 汎化性能は、訓練に使っていない検証データやテストデータの精度・損失などで評価する。訓練データでの精度だけが高くても、未知データで低ければ汎化性能が高いとはいえない。
- **過学習（overfitting）**は、モデルが訓練データの特徴やノイズへ過度に適合し、訓練データでは高い精度を示す一方、未知の検証・テストデータでは精度が低下する状態である。反対に、モデルが単純すぎるなどの理由で訓練データにも十分適合できず、訓練・未知データの両方で精度が低い状態を**未学習（underfitting）**という。
- **データ拡張（data augmentation）**は、元の訓練データに、正解ラベルの意味を保つ加工を施して訓練例の種類・量を増やす方法である。画像なら回転、反転、切り抜き、拡大縮小、明るさの変更などが例となる。モデルが特定の訓練例を丸暗記しにくくなるため、過学習の抑制に役立つ。画像の設問の正解は **イ**。
- データ拡張のほか、モデルを単純にする、L1・L2正則化やDropoutを使う、検証誤差が悪化する前に学習を止める早期終了（early stopping）、適切な訓練データを増やす、といった方法も過学習対策になる。

| 選択肢の説明 | 判断 |
| --- | --- |
| 訓練データをテストデータにも使用する | 未知データに対する性能を評価できず、データリーケージになる。訓練・検証・テストデータは適切に分離する。 |
| 元の訓練データへ加工を施して量を増やす | データ拡張であり、過学習を抑えて汎化性能を高める対策になる。 |
| モデルをより複雑にする | 表現力が過剰になり、訓練データを記憶しやすくなって過学習が悪化する場合がある。 |
| 汎化性能を下げる | 過学習対策の目的は、未知データに対する汎化性能を**高める**ことである。 |

| 訓練データでの性能 | 未知データでの性能 | 状態 |
| --- | --- | --- |
| 高い | 高い | 適切に学習でき、汎化性能も高い |
| 高い | 低い | 過学習。訓練データを覚えすぎている |
| 低い | 低い | 未学習。モデルや学習が不十分 |

- モデル選択やハイパーパラメータ調整には**検証データ**を使い、最終的な汎化性能の評価には、それまで調整に使っていない**テストデータ**を使う。テストデータを何度も見て調整すると、そのテストデータへ間接的に過学習し、公正な評価ができなくなる。

### スマートファクトリーにおけるマシンビジョン

- **マシンビジョン**は、カメラなどで取得した画像をコンピュータで処理・認識し、検査、計測、位置決め、仕分けなどを自動化する技術である。
- スマートファクトリーでは、製品表面の傷、汚れ、欠け、組立不良などを画像から検出し、人による目視検査をAIで代替・支援して、検査効率や品質の安定性を高める用途が代表的である。問28の正解は **エ**。

| 選択肢の説明 | 主な用途・技術 |
| --- | --- |
| 入出荷データから需要を予測して生産数を最適化 | 需要予測・生産計画最適化 |
| VRゴーグルへ作業状況に応じたガイドを表示 | AR／VRによる作業支援 |
| 設計変更内容を整理して製造現場へ伝達 | 設計・製造情報の管理、ナレッジ活用 |
| 目視検査をAIで代替して検査効率を向上 | **マシンビジョン** |
