### プロジェクトのスコープ管理

- **スコープ**は、そのプロジェクトで「何を成果として作るか」「どの作業をプロジェクト内で実施するか」という範囲を表す。
- 令和6年度秋期 高度試験 午前I 問18の正解は **ウ**。外部システムのリリース遅延を受けて、**外部システムとの連携作業を現在のプロジェクトから外し、別プロジェクトで実施する**判断は、実施範囲そのものを変更しているのでスコープ管理に当たる。

| 選択肢 | 主な管理領域 | 理由 |
| --- | --- | --- |
| ア 開発ツールの教育期間を2日延長 | スケジュール管理 | 作業期間を変更している |
| イ 見積超過が判明して追加予算を確保 | コスト管理 | 予算・費用を調整している |
| **ウ 外部システム連携作業を別プロジェクトへ移す** | **スコープ管理** | **現在のプロジェクトで実施する作業範囲を変更しているので正解** |
| エ テスト担当者を交代 | 資源管理 | 人員配置を変更している |

#### スコープを見分けるコツ

- 「いつやるか」 → スケジュール
- 「いくら使うか」 → コスト
- 「誰がやるか」 → 資源
- **「何をこのプロジェクトでやるか」 → スコープ**

- スコープを変更すると、納期・費用・品質・リスクにも影響し得るため、実務では他の管理領域と独立ではない。ただし試験では、**直接変更している対象**を見ると判別しやすい。

### ファストトラッキングとクラッシング

- **ファストトラッキング（fast tracking）**は、本来は順番に行う作業を一部並行させ、後工程を前倒しで開始してスケジュールを短縮する方法である。
- 令和6年度秋期 高度試験 午前I 問19の正解は **エ**。設計が全て終わるのを待たず、**設計が終わったモジュールから順にプログラム開発を開始する**ことで、設計工程と開発工程を重ねているためファストトラッキングに当たる。

```text
通常:
設計 ─────────→ 開発 ─────────→

ファストトラッキング:
設計 ─────────→
       開発 ─────────→
      ↑ 前工程が完全終了する前に後工程を開始
```

| 選択肢 | 判断 |
| --- | --- |
| ア クリティカルパス上の作業へ人的資源を追加 | **クラッシング**。資源投入で期間を短縮する方法 |
| イ コスト削減のため残業を禁止 | スケジュール短縮の技法ではない |
| ウ 完了予定日を延期 | 遅れを受け入れて期日を後ろへ動かしており、短縮ではない |
| **エ 設計済みモジュールから開発を開始** | **ファストトラッキングなので正解** |

#### ファストトラッキングとクラッシングの違い

- **ファストトラッキング**：作業の**順番・重なり方**を変える。追加費用を必須としないが、前工程の変更による手戻りや品質リスクが増えやすい。
- **クラッシング**：人員・設備・外注などの**資源を追加**して期間を短縮する。一般に追加コストが発生する。
- 覚え方は、**重ねる = fast tracking、増やす = crashing**。
