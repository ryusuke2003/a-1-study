# プロジェクト管理

## 2026-08-29

### タックマンモデル

- タックマンモデルは、チームの発展を5段階で捉えるモデルである。順序は、**成立期（Forming）→ 動乱期（Storming）→ 安定期（Norming）→ 遂行期（Performing）→ 終結期（Adjourning）**である。
- **成立期**は、チームが作られた直後で、メンバーが目的や役割を探りながら関係を築き始める段階である。
- **動乱期**は、メンバーごとの考え方・価値観・意見の違いが明確になり、意見を主張し合い、対立や混乱が生じやすい段階である。画像の設問の正解は **エ**。
- **安定期**は、役割分担やルールが整い、メンバー間の協力関係が安定する段階である。
- **遂行期**は、チームが自律的に協働し、目標達成に向けて高い成果を出す段階である。
- **終結期**は、目標達成やプロジェクト終了に伴い、活動を完了・振り返り・解散する段階である。

### 見分け方

| 状態 | 段階 |
|---|---|
| 目的・役割を探り、関係を築き始める | 成立期 |
| 意見や価値観がぶつかり、主張・対立が表面化する | 動乱期 |
| ルールと役割が定まり、協力が安定する | 安定期 |
| 自律的に協働して成果を出す | 遂行期 |
| 活動を完了し、振り返りや解散を行う | 終結期 |

### プログラムマネジメント

- プログラムマネジメントは、事業目標・組織戦略の実現に向けて、相互に関連する複数のプロジェクトを一つのプログラムとして統合的に管理し、連携や相互作用から価値を高める考え方である。問23の正解は **ア**。
- 個々のプロジェクトをさらに細分化して管理することではない。
- **PMO（Project Management Office）**は、組織全体のプロジェクトマネジメントを支援し、標準化・能力・品質向上などを担う専門組織である。問23の **エ** はPMOの説明。

| 着眼点 | 用語 |
| --- | --- |
| 複数プロジェクトを統合し、戦略実現・価値向上を目指す | プログラムマネジメント |
| 組織全体のプロジェクト管理を支援する専門組織 | PMO |

## 2026-09-06

### スクラムのイベント

- **スプリントレビュー（Sprint Review）**は、スプリントの終わりに、完成したインクリメント（作業の成果）をステークホルダーへ提示するイベントである。プロダクトゴールに対する進捗を共有し、フィードバックを得ながら、次に必要となる作業やスコープをプロダクトバックログへ反映・調整する。
- したがって、「成果をプレゼンテーションし、プロダクトゴールへの進捗を話し合い、必要に応じてスコープを調整する」という説明は、**スプリントレビュー**を指す。単なる報告会ではなく、成果と状況を基に今後の方向性を協働で確認・調整する場である。

| イベント | 主な目的 | 見分け方 |
| --- | --- | --- |
| スプリントプランニング | 次のスプリントで何を、なぜ、どのように行うかを計画し、スプリントゴールとスプリントバックログを作る | **これから行う作業を決める** |
| デイリースクラム | 開発者が毎日、スプリントゴールに対する進捗を点検し、当日の計画を調整する | **毎日の短い進捗確認** |
| スプリントレビュー | 成果をステークホルダーへ提示し、フィードバックと進捗を基に今後のスコープを調整する | **成果の提示・関係者との確認** |
| スプリントレトロスペクティブ | チームの進め方・協働・品質などを振り返り、次のスプリントで改善する方法を決める | **チームの仕事の仕方を改善** |

- **retrospective** は英語で「回顧的な、過去を振り返る」という意味で、`retro` は「後ろ・過去」、`spect` は「見る」という語感を持つ。Scrumではこの意味から、スプリントを振り返ってチームの進め方を改善するイベント名になっている。
- 試験では、**Review = 成果物・進捗を関係者と確認する**、**Retrospective = 自分たちの仕事の進め方を振り返って改善する**と区別するとよい。
- レトロスペクティブでは、何がうまくいったか、何がうまくいかなかったか、次のスプリントで何を改善するかを話し合う。

### EVMのCPI・SPI・TCPIと対策

- **EVM（Earned Value Management）**は、出来高を用いてコストとスケジュールの進捗を評価する手法である。**CPI（Cost Performance Index）**はコスト効率、**SPI（Schedule Performance Index）**はスケジュール効率を表す。
- CPIとSPIは、`1`が計画どおりの基準である。**CPI < 1**は、得られた出来高に対して実コストが多く、コスト効率が悪いことを表す。**SPI < 1**は進捗遅れ、**SPI = 1**は計画どおり、**SPI > 1**は予定より進んでいることを表す。
- **TCPI（To-Complete Performance Index）**は、目標予算内に収めるために、残作業で必要となるコスト効率である。BAC（完成時総予算）を目標にしたTCPIが **1.2** なら、残作業では計画時を上回る1.2のコスト効率が必要であり、現状のCPI=0.9のままではBAC超過のおそれがある。
- **コンティンジェンシー予備費（contingency reserve）**は、**既知のリスクに備えて確保しておく予備費**である。あらかじめ識別・評価したリスクが実際に発生したときの対応費用として使う。
- 設問の `CPI = 0.9`、`SPI = 1.1`、`TCPI = 1.2` では、コスト効率は計画より悪い一方、スケジュールは予定より進んでいる。BACに収めるには残作業で1.2のコスト効率が必要なので、コスト効率を改善する対策、又は**コンティンジェンシー予備費**の使用を検討するのが適切である。正解は **イ**。

| 状況 | 判断・対策 |
| --- | --- |
| CPI < 1 | コスト効率が悪く、完成時予測コストの増加を確認する。必要なら残作業の効率改善や予備費の使用を検討する。 |
| SPI < 1 | スケジュール遅延。並行して実施できる作業を重ねる**ファストトラッキング**、又は資源を追加する**クラッシング**などによる短縮を検討する。 |
| TCPI > 1 | 目標予算内に収めるには残作業で計画以上のコスト効率が必要。達成可能性と対策を確認する。 |

- **クラッシング（crashing）**は、工期を短縮するために、**クリティカルパス上の作業**へ人員・設備・外注などの資源を追加投入する方法である。追加コストが発生し得るため、短縮できる日数と追加コストを比較して実施対象を選ぶ。プロジェクト外部から要員を調達し、クリティカルパス上の作業に投入する選択肢がこれに当たる。画像の設問の正解は **エ**。
- **ファストトラッキング（fast tracking）**は、本来は順次行う作業を、前工程が完全に終わる前から後工程の一部を開始して重ねる方法である。選択肢**ウ**はこの説明に当たり、手戻り・品質低下などのリスクが増え得る。
- クラッシングとファストトラッキングは、既に`SPI < 1`となった遅延への対策だけでなく、計画段階で要求された工期へ収めるためのスケジュール短縮にも用いる。
- 前後関係を見直して実施順序を変えること（選択肢**ア**）や、作業を分割して同時実施可能な部分を増やすこと（選択肢**イ**）は、一般的な計画・作業設計の見直しである。資源を追加するというクラッシングの定義そのものではない。

## 2026-09-10

### EVMのPV・EV・ACからコストと完了時期を判断する

- 令和6年度春期 高度試験 午前I 問18の正解は **ア：計画よりコストは多くなり、完了は遅くなる**。
- **PV（Planned Value）**は現時点までに完了する予定だった作業の予算、**EV（Earned Value）**は実際に完了した作業を予算額で表した出来高、**AC（Actual Cost）**は実際に掛かったコストである。
- 図では `PV > AC > EV` となっている。コストは `AC > EV` なので、得られた出来高より実コストが多く、**コスト効率が悪い**。スケジュールは `EV < PV` なので、計画より出来高が少なく、**進捗が遅れている**。
- コスト効率とスケジュール効率がこのまま推移するという条件から、最終的なコストは計画より多くなり、完了時期は予定より遅くなると見通せる。

| 指標・差異 | 式 | この図での判断 |
| --- | --- | --- |
| コスト差異（CV） | `EV - AC` | 負：コスト超過 |
| コスト効率指数（CPI） | `EV / AC` | 1未満：コスト効率が悪い |
| スケジュール差異（SV） | `EV - PV` | 負：進捗遅れ |
| スケジュール効率指数（SPI） | `EV / PV` | 1未満：進捗遅れ |

#### 選択肢の判断

| 選択肢 | 判断 |
| --- | --- |
| **ア 計画に比べてコストは多くなり、プロジェクトの完了は遅くなる** | **正しい。`AC > EV`からコスト超過、`EV < PV`から進捗遅れと判断する** |
| イ 計画に比べてコストは多くなり、プロジェクトの完了は早くなる | 誤り。コストは多くなるが、`EV < PV`なので完了は遅くなる見通し |
| ウ 計画に比べてコストは少なくなり、プロジェクトの完了は遅くなる | 誤り。完了は遅くなるが、`AC > EV`なのでコストは多くなる見通し |
| エ 計画に比べてコストは少なくなり、プロジェクトの完了は早くなる | 誤り。コストとスケジュールの両方の判断が逆である |

- 覚え方は、**コストはEVとAC、進捗はEVとPVを比べる**。`EV`が比較の中心になる。
