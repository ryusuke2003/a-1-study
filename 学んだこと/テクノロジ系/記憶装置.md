# 記憶装置

## 2026-08-28

### キャッシュメモリの置換アルゴリズム

キャッシュが満杯で新しいブロックをロードするとき、どのブロックを追い出すかを決める規則である。

- **FIFO（First In, First Out）**: 最も早くキャッシュへロードされたブロックを置換する。参照回数や最終参照時刻は使わない。
- **LFU（Least Frequently Used）**: 参照回数が最も少ないブロックを置換する。
- **LIFO（Last In, First Out）**: 最も最後にキャッシュへロードされたブロックを置換する。
- **LRU（Least Recently Used）**: 最終参照時刻が最も古く、最も長く使われていないブロックを置換する。

問題の表では、C2の最終参照時刻が `0:05` で最も古いため、C2を置換対象にするのは **LRU（エ）** である。

## 2026-09-06

### 仮想記憶・ページング・ページ置換

- **仮想記憶**は、各プロセスに主記憶（RAM）の物理容量とは独立した仮想アドレス空間を見せ、必要な部分だけを主記憶へ置くことで、物理メモリより大きなアドレス空間を扱えるようにする仕組みである。全内容が同時にRAMへ存在するわけではなく、主記憶にない部分は補助記憶を利用する。
- **ページング**は、仮想アドレス空間を固定長の**ページ**、主記憶を同じ大きさの**ページ枠（フレーム）**に分け、ページテーブルを用いて仮想ページと物理ページ枠を対応付ける仮想記憶の管理方式である。仮想記憶が目的・仕組み全体、ページングがその実現方法の一つに当たる。
- 仮想記憶では、参照するページが主記憶に存在しないと**ページフォールト**が発生し、補助記憶から主記憶へページを読み込む。この処理を**ページイン**という。
- **ページ置換**は、ページフォールト時に空きページ枠がない場合、主記憶上のどのページを追い出して新しいページの格納場所を作るか決める処理である。**LRU（Least Recently Used）**では、主記憶にあるページのうち、最後に参照された時点が最も古いページを置換対象にする。
- 主記憶に既にあるページを参照した場合、置換は起こらないが、そのページの最終参照時点は更新される。LRUを手計算するときに見落としやすい点である。
- ページ枠の番地はページを入れ替えても変わらず、その番地に格納されているページだけが変わる。

関係は、`仮想記憶（仕組み全体） → ページング（ページ単位の管理方式） → ページ置換（空き枠不足時の追出し処理）` と整理できる。ページフォールトが起きても空きページ枠があればページインだけを行い、ページ置換は必要ない。

問6では、最初の `1 → 2 → 3 → 4` によって、ページ1、2、3、4がそれぞれ4000、5000、6000、7000番地へページインされる。その後を追跡すると次のようになる。

| 参照ページ | 動作 | 置換後の内容 |
| ---: | --- | --- |
| 2 | 主記憶にあるので最終参照を更新 | 4000:1、5000:2、6000:3、7000:4 |
| 5 | 最終参照が最も古い1を置換 | 4000:5、5000:2、6000:3、7000:4 |
| 3 | 主記憶にあるので最終参照を更新 | 4000:5、5000:2、6000:3、7000:4 |
| 1 | 最終参照が最も古い4を置換 | 4000:5、5000:2、6000:3、7000:1 |
| 6 | 最終参照が最も古い2を置換 | 4000:5、5000:6、6000:3、7000:1 |
| 5 | 主記憶にあるので最終参照を更新 | 4000:5、5000:6、6000:3、7000:1 |
| 4 | 最終参照が最も古い3を置換 | 4000:5、5000:6、6000:4、7000:1 |

最後に参照するページ4は、ページ3があった**6000番地**へページインされる。したがって正解は **ウ（6000）** である。

## 2026-09-07

### ページング方式とセグメンテーション方式の違い

- 令和6年度秋期 高度試験 午前I 問6の正解は **エ：主記憶の外部断片化が発生しない**。
- **ページング方式**は、仮想アドレス空間を固定長のページ、主記憶を同じ大きさのページ枠に分けて管理する。ページは空いている任意のページ枠へ配置できるため、可変長領域の間に小さな空きが散らばって「合計では空いているのに連続領域を確保できない」という**外部断片化**が発生しない。
- ただし、固定長のページ枠の一部が使われずに余る**内部断片化**は起こり得る。
- **セグメンテーション方式**は、コード・データなどプログラム上の論理的な単位を可変長のセグメントとして扱う。そのため論理単位でのアクセス保護や共有に向く一方、可変長領域を配置するので外部断片化が起こり得る。

| 選択肢 | 主に対応する方式 | 判断 |
| --- | --- | --- |
| ア 論理的な単位でアクセス保護 | セグメンテーション | ページング固有の長所ではない |
| イ プログラム間で記憶領域を容易に共有 | セグメンテーション | 論理的なセグメント単位で共有しやすい |
| ウ 実行時に記憶領域の大きさを動的に変更 | セグメンテーション | 可変長の論理単位を扱う特徴 |
| **エ 主記憶の外部断片化が発生しない** | **ページング** | **固定長のページ枠を使うため正解** |

#### 覚え方

- **ページング = 固定長 → 外部断片化なし**
- **セグメンテーション = 論理単位・可変長 → 保護や共有に向く**
