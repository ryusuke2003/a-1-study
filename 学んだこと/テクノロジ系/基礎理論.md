# 基礎理論

## 2026-08-28

### M/M/1待ち行列モデルと利用率

- M/M/1は、到着がポアソン分布、サービス時間が指数分布、窓口が1台（1サーバ）、待ち行列長に制限がない待ち行列モデルである。
- 平均サービス時間を `T` 秒とすると、サービス率は `μ = 1/T` である。
- 利用率を `ρ = λ/μ` としたとき、M/M/1の平均待ち時間（サービス開始まで）は `Wq = ρ / (μ(1 - ρ))` で表せる。
- `Wq ≤ T = 1/μ` を満たすには、`ρ/(1-ρ) ≤ 1`、すなわち `ρ ≤ 1/2` となる。したがって利用率の上限は **50%** である。

### 要確認

- 「平均待ち時間」が待ち行列内の待ち時間 `Wq` ではなく、サービス時間を含む系内滞在時間 `W` を指す場合は式が異なる。問題文の定義を確認して使い分ける。

## 2026-09-06

### スタックから取り出せるデータの順序

- **スタック**は、最後に挿入したデータから最初に取り出す **LIFO（Last In, First Out：後入れ先出し）** のデータ構造である。挿入をpush、取出しをpopという。
- スタックがLIFOになるのは、特定の問題でたまたまそうなるからではなく、**スタックというデータ構造の操作規則そのもの**である。通常、追加と取出しは同じ端であるスタックの最上部（top）だけに対して行う。
- 配列や連結リストを使ってスタックを実装することはできるが、途中の要素を任意に取り出す操作はスタックのpopではない。内部実装に別の操作が可能でも、スタックとして利用するときはLIFOのインタフェースに従う。
- A、B、Cの順にしか入力できない場合でも、各データをpushする時点とpopする時点を変えることで、出力順序を変えられる。ただし、スタック内部では上にあるデータを飛び越えて下のデータを取り出すことはできない。

| 出力順 | 操作の一例 | 可否 |
| --- | --- | --- |
| ABC | Aをpush・popし、B、Cも同様に処理 | 可能 |
| ACB | Aをpop後、B、Cをpushし、C、Bの順にpop | 可能 |
| BAC | A、Bをpushし、B、Aの順にpop後、Cを処理 | 可能 |
| BCA | A、BをpushしてBをpopし、CをpushしてC、Aの順にpop | 可能 |
| CBA | A、B、Cを全てpushし、C、B、Aの順にpop | 可能 |
| CAB | Cを最初に出すにはA、B、Cをpushする必要がある。Cをpopした後はBが最上部なので、Aを先に取り出せない | 不可能 |

- 3個の全順列は `3! = 6` 通りだが、不可能なCABを除くため、可能な出力順は **5通り**。画像の設問の正解は **ウ**。
- 入力順が固定されたn個の異なるデータを一つのスタックで処理して作れる出力順の数は、一般には**カタラン数** `Cₙ = (2n)! / (n!(n+1)!)` で表される。n=3では `C₃ = 5` となる。ただし、3個程度なら公式より実際に列挙する方が確実である。
- FIFO（First In, First Out：先入れ先出し）のキューでは、A、B、Cの順に入れたデータは原則としてABCの順に取り出される。スタックのLIFOと混同しない。

## 2026-09-07

### 交差検証と、混同しやすい機械学習の手法

- IPAシラバスでは、AI・機械学習は**テクノロジ系 → 基礎理論 → 情報に関する理論**に位置付けられている。交差検証、正則化、アンサンブル学習も機械学習の代表的な評価・精度向上手法として扱われる。
- **交差検証（cross-validation）**は、限られたデータを複数のグループ（fold）へ分け、学習に使う部分と評価に使う部分を順番に入れ替えて、未知データに対する**汎化性能**を評価する方法である。代表的な**k-fold cross-validation**では、データをk個に分割し、1個を検証用、残りを学習用としてk回繰り返し、評価値を平均する。
- 交差検証は、単に一度だけ訓練用と評価用へ分ける**ホールドアウト法**より、複数の分割で評価できるため、特定の分け方に結果が左右されにくい。ただし、モデル選択やハイパーパラメータ調整に交差検証を使う場合でも、最終的な性能確認用の**テストデータは交差検証へ混ぜずに残しておく**。
- 交差検証の目的は**モデルの評価**であり、モデルそのものへペナルティを加えたり、複数モデルを統合したり、複数タスクを同時学習させたりする手法ではない。令和6年度秋期 高度試験 午前I 問1では、「データを複数グループに分割し、一部を学習、残りを評価に使い、順に入れ替える」という記述が交差検証に当たり、正解は **エ**。

| 手法 | 何をするか | 主な目的・見分け方 |
| --- | --- | --- |
| 交差検証 | データの学習役・評価役を入れ替えて複数回評価する | 未知データへの汎化性能を安定して評価する |
| 正則化 | 損失関数へモデルの複雑さに対するペナルティを加える | 過度に複雑なモデルを抑え、過学習を防ぐ |
| アンサンブル学習 | 複数のモデルの予測を組み合わせる | 単一モデルより安定した予測や精度向上を狙う |
| マルチタスク学習 | 関連する複数の課題を一つのモデルで同時に学習する | 課題間で共通する表現・知識を共有する |

#### 正則化

- **正則化（regularization）**は、学習時の損失に「モデルを複雑にし過ぎないためのペナルティ」を加え、訓練データへの過度な適合を抑える手法である。交差検証が**評価の方法**なのに対し、正則化は**学習の仕方を変える方法**である。
- **L1正則化**は重みの絶対値の合計をペナルティに使い、不要な重みが0になりやすいため、疎なモデルや特徴選択につながることがある。**L2正則化**は重みの二乗和をペナルティに使い、大き過ぎる重みを全体的に抑える。
- 正則化を強くし過ぎるとモデルが単純になり過ぎ、訓練データにも適合できない未学習につながることがある。

#### アンサンブル学習

- **アンサンブル学習（ensemble learning）**は、複数のモデルの予測を多数決・平均・重み付き結合などでまとめ、一つの予測として利用する考え方である。
- **Random Forest**は、異なるデータや特徴の組合せで多数の決定木を作り、その結果を統合する代表的な**バギング系**の手法である。
- **Boosting**は、複数の弱学習器を順番に学習させ、前段までの誤りを後続の学習器が補うように組み合わせて強い予測器を作る考え方である。例えばAdaBoostは誤分類したデータを重視し、Gradient Boostingはそれまでの予測誤差を補う方向へ逐次学習する。
- 交差検証は複数モデルの予測を組み合わせる方法ではなく、学習・評価用データの分割を変えながら性能を測る方法である。

#### マルチタスク学習

- **マルチタスク学習（multi-task learning）**は、関連する複数の課題を一つのモデルで同時に学習し、課題間で共通する特徴表現を共有する方法である。
- 例えば、一つの画像から「物体の種類を分類する」と「物体の位置を推定する」のような関連課題を同時に学習させる構成がある。課題が関連していれば、一方の学習で得た表現が他方にも役立ち、汎化性能の向上につながる場合がある。
- 複数の独立モデルの予測結果を後から組み合わせるアンサンブル学習とは異なり、マルチタスク学習は**一つのモデル内部で複数課題を共同学習する**点が中心である。
