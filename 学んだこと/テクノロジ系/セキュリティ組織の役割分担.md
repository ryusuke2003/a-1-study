# セキュリティ組織の役割分担

## 2026-09-12

### SOC・CSIRT・PSIRTの違い

SOC・CSIRT・PSIRTはどれもセキュリティに関わるが、**何を主に見るか**と**どの段階を担当するか**が異なる。

| 組織 | 一言で覚える | 主な対象 | 主な役割 |
| --- | --- | --- | --- |
| **SOC（Security Operations Center）** | **見張る** | ログ、アラート、端末・ネットワークの不審な挙動 | 継続監視、検知、一次分析、必要に応じたエスカレーション |
| **CSIRT（Computer Security Incident Response Team）** | **事故対応する** | 自組織で発生した、又は発生が疑われるセキュリティインシデント | 影響範囲の確認、封じ込め、原因調査、復旧、関係者調整、再発防止 |
| **PSIRT（Product Security Incident Response Team）** | **製品の脆弱性を直す** | 自社が開発・提供する製品やサービスの脆弱性 | 脆弱性報告の受付、影響評価、修正・パッチの調整、情報公開、関係者調整 |

### SOCとCSIRTの関係

SOCは、ログやアラートを日常的に監視して**怪しいものを見つける側**と捉えると分かりやすい。例えば、EDRやSIEMなどのアラートから「ある端末が普段と違う外部通信をしている」と気付いたら、内容を確認し、インシデントの疑いが強ければCSIRTへ連携する。

CSIRTは、その事象を**実際のインシデントとしてどう処理するか**を担う。感染端末の隔離、侵害されたアカウントの停止、影響範囲の調査、復旧、社内外への連絡、原因分析や再発防止などを進める。

```text
SOC
「怪しい通信・アラートを見つけた」
        ↓
CSIRT
「事故か判断して、封じ込め・調査・復旧する」
```

したがって試験対策では、**SOC = 検知・監視、CSIRT = インシデント対応**と切り分ける。

### PSIRTとCSIRTの違い

PSIRTは、会社そのものが攻撃を受けたときの対応ではなく、**自社製品・サービスに見つかった脆弱性への対応**を主に担当する。

例えば、外部のセキュリティ研究者から「御社のWeb製品に認証を回避できる脆弱性がある」と報告された場合、PSIRTは報告を受け付け、製品担当者と影響を調べ、修正版や緩和策を準備し、必要に応じて利用者への告知や脆弱性情報の公開を調整する。

```text
外部研究者・利用者
「御社製品に脆弱性があります」
        ↓
PSIRT
「影響を評価して、修正・公開を調整する」
```

一方、その脆弱性を悪用されて**自社の社内システムが侵害された**なら、組織内のインシデント対応としてCSIRTが関わる可能性がある。同じ出来事で複数の組織が連携することはあるため、名称だけで完全に分離された部署だと考えるのではなく、**主な対象と役割**で見分ける。

### 覚え方

- **SOC = 見張る**
- **CSIRT = 事故対応する**
- **PSIRT = 製品の脆弱性を直す**

さらに一段だけ具体化すると、

- **SOC = 見つける**
- **CSIRT = 被害を止めて復旧する**
- **PSIRT = 製品側の弱点を評価して修正・公開する**

と整理すると、選択肢を区別しやすい。
