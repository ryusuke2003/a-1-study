## 2026-09-07

### コンパイラの処理順序と各解析の違い

- コンパイラの典型的な流れは、**字句解析 → 構文解析 → 意味解析 → 最適化 → コード生成**。
- 令和6年度秋期 高度試験 午前I 問7は「コード生成までに行う処理のうち最後」を聞いているので、正解は **ウ：最適化**。

| 処理 | 試験での見分け方 |
| --- | --- |
| **字句解析** | 文字列を識別子・予約語・数値・演算子などの**トークン**へ分ける |
| **構文解析** | トークンの並びが文法に従っているか確認する |
| **意味解析** | 型や変数の宣言など、意味上の整合性を確認する |
| **最適化** | 結果を変えずに、処理を効率化する |
| **コード生成** | 実行可能な目的コードへ変換する |

覚え方は、**「単語に切る → 文法を見る → 意味を見る → 効率化 → コードにする」**。

## 2026-09-10

### デッドロック

- **デッドロック**は、複数の処理が、互いに相手の保持する資源の解放を待ち続け、どの処理も先へ進めなくなる状態である。OSのプロセスによる資源取得や、データベースのトランザクションによるロック取得などで発生する。
- 典型例は、処理Aが資源Xを保持したまま資源Yを待ち、処理Bが資源Yを保持したまま資源Xを待つ場合である。

```text
処理A：資源Xを保持 → 資源Yを待つ
                         ↑
処理B：資源Yを保持 → 資源Xを待つ
```

### デッドロックの成立条件と対策

- デッドロックが成立するには、次の四条件が同時に満たされる必要がある。

| 条件 | 意味 |
| --- | --- |
| 相互排他 | 一つの資源を同時に一つの処理しか利用できない |
| 保持と待ち | 資源を保持したまま、別の資源を待つ |
| 横取り不可 | 他の処理が保持する資源を強制的に取り上げられない |
| 循環待ち | 複数の処理が輪になって互いの資源を待つ |

- **予防**は四条件のいずれかを成立させない方法である。代表例は、全処理で資源を取得する順序を統一して循環待ちを防ぐことや、必要な資源をまとめて確保して保持と待ちを防ぐことである。
- **検出と回復**では、待ち関係の循環を検出し、いずれかの処理・トランザクションを中止又はロールバックして資源を解放する。タイムアウトにより待ちを打ち切る方法もある。
- データベースでは、トランザクションを短くする、複数の表・行を常に同じ順序でロックする、といった設計が発生可能性の低減に有効である。

## 2026-09-10

### 資源の占有順序からデッドロックを判定する

- 令和6年度春期 高度試験 午前I 問6の正解は **イ：C、D**。
- 表の数字は各プロセスが資源を占有する順番なので、次のように読み替える。

| プロセス | 資源の占有順序 |
| --- | --- |
| A | X → Y → Z |
| B | X → Y → Z |
| C | Z → X → Y |
| D | Z → Y → X |

- **AとB**は同じ順序で資源を取得する。先にXを取得した側がY、Zへ進み、もう一方は最初のXで待つため、互いに別の資源を保持して待つ循環は作られない。
- **AとC**では、AがXとYを保持してZを待ち、CがZを保持してXを待つ実行順序があり、循環待ちになる。
- **AとD**では、AがXとYを保持してZを待ち、DがZを保持してYを待つ実行順序があり、循環待ちになる。

```text
AとC：AはZ待ち ← CがZを保持
       CはX待ち ← AがXを保持

AとD：AはZ待ち ← DがZを保持
       DはY待ち ← AがYを保持
```

#### 選択肢の判断

| 選択肢 | 判断 |
| --- | --- |
| ア B、C、D | 誤り。BはAと同じ順序で取得するため、Aとのデッドロックは起こらない |
| **イ C、D** | **正しい。CとDは、どちらもAとの循環待ちが起こり得る** |
| ウ Cだけ | 誤り。DでもAとの循環待ちが起こり得る |
| エ Dだけ | 誤り。CでもAとの循環待ちが起こり得る |

- 判定では、単に取得順が異なるかを見るのではなく、**一方が保持する資源を他方が待ち、その他方が保持する資源を一方が待つ実行順序が存在するか**を確認する。全プロセスで資源取得順序を統一すれば、循環待ちを防止できる。
