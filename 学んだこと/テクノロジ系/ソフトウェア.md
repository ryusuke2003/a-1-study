## 2026-09-07

### コンパイラの処理順序と、字句解析・構文解析・意味解析・最適化の違い

- **コンパイラ**は、高水準言語で書かれたソースコードを解析し、最終的に機械語や目的コードなどへ変換するソフトウェアである。典型的な処理の流れは、**字句解析 → 構文解析 → 意味解析 → 最適化 → コード生成**と整理できる。
- 令和6年度秋期 高度試験 午前I 問7では、「コード生成までに行う処理のうち、最後に行うもの」が問われている。選択肢の中では**最適化**が最後なので、正解は **ウ**。
- 実際のコンパイラでは中間コード生成や複数段階の最適化などが入り、各処理がより細かく分かれることもある。試験では、各工程の**入力と役割**を区別できることが重要である。

| 処理 | 何を見るか | 主な役割 | イメージ |
| --- | --- | --- | --- |
| **字句解析** | 文字列 | 文字の並びを、識別子・予約語・数値・演算子などの**トークン**へ分割する | `int x = 10;` → `int`、`x`、`=`、`10`、`;` |
| **構文解析** | トークン列 | 文法規則に従った並びか確認し、構文木などを作る | 括弧や演算子、文の組立てが文法的に正しいか |
| **意味解析** | 構文と宣言・型など | 文法的には正しくても、型や変数の使い方などに意味上の矛盾がないか確認する | 未宣言変数、型の不整合などを確認 |
| **最適化** | 解析済みの中間表現など | 結果を変えずに、処理速度・コードサイズ・資源利用などを改善する | 不要な計算の除去、定数式の簡約など |
| **コード生成** | 最適化された中間表現など | CPUなどが実行できる目的コードへ変換する | 命令選択、レジスタ利用など |

#### 見分け方

- **文字を単語のような単位へ切る** → 字句解析
- **文法として正しい並びかを見る** → 構文解析
- **型・宣言・演算の意味が矛盾しないかを見る** → 意味解析
- **同じ結果のまま速く・小さくする** → 最適化
- **実行できる命令へ落とす** → コード生成

例えば `x = 1 + 2;` なら、字句解析で `x`、`=`、`1`、`+`、`2`、`;` のように分け、構文解析で「代入文」として組み立て、意味解析で `x` の宣言や型を確認する。その後、最適化で `1 + 2` を `3` に置き換えられる場合があり、最後に目的コードを生成する。
